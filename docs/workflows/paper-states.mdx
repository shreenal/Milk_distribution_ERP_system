The `order_paper.status` field is an `OrderPaperStatus` enum with exactly five values: `DRAFT`, `NIGHT_SUBMITTED`, `MORNING_SUBMITTED`, `FINALIZED`, `REOPENED`. Every write in the system consults it. This page is the definitive reference for what each state means, what transitions are legal, and what side effects each transition triggers.

## States

| State | Meaning | Reached by |
| --- | --- | --- |
| `DRAFT` | Paper created; night entry in progress | Paper creation by `EMPLOYEE` (or `ADMIN` via role hierarchy) |
| `NIGHT_SUBMITTED` | Night phase closed; morning phase in progress | `POST /papers/:id/submit-night` by `EMPLOYEE` |
| `MORNING_SUBMITTED` | Delivery done; awaiting cash settlement \+ admin review | `POST /papers/:id/submit-morning` by `EMPLOYEE` |
| `FINALIZED` | Locked; day is closed | `POST /papers/:id/finalize` by `ADMIN` |
| `REOPENED` | Correction mode after finalize | `POST /papers/:id/reopen` by `ADMIN` with a reason |

## Transitions

Only these five transitions are legal. Any other attempted move is rejected by `WorkflowStateService.validateTransition()` with a `BadRequestException`.

| From | To | Role | Endpoint | Side effects |
| --- | --- | --- | --- | --- |
| `-` | `DRAFT` | `EMPLOYEE` | `POST /papers` | Auto-creates one `order_sheet` per active delivery group |
| `DRAFT` | `NIGHT_SUBMITTED` | `EMPLOYEE` | `POST /papers/:id/submit-night` | Stamps `night_entry_submitted_at` |
| `NIGHT_SUBMITTED` | `MORNING_SUBMITTED` | `EMPLOYEE` | `POST /papers/:id/submit-morning` | Stamps `morning_entry_submitted_at`; auto-generates `distributor_transfer` rows via `DistributorTransferService.generateTransfer` |
| `MORNING_SUBMITTED` | `FINALIZED` | `ADMIN` | `POST /papers/:id/finalize` | Stamps `finalized_at` |
| `FINALIZED` | `REOPENED` | `ADMIN` | `POST /papers/:id/reopen` | Stamps `reopened_at`, sets `reopen_reason` |
| `REOPENED` | `FINALIZED` | `ADMIN` | `POST /papers/:id/finalize` | Stamps `finalized_at` (does not clear `reopened_at` or `reopen_reason`) |

## Editability per state

The exact per-module rules live in `WorkflowStateService`. This summary lists what each `canEdit…` helper returns true for in the current implementation.

<AccordionGroup>
  <Accordion title="DRAFT — editable modules">
    - Orders: night save (`canEditNightEntries` → true only in `DRAFT`)
    - Collections: night save (`canEditNightCollections` → `DRAFT`, `NIGHT_SUBMITTED`, `REOPENED`)
    - Vehicle Allocation: NIGHT session (`canEditVehicleAllocations` matches the active execution session)

    Everything else is read-only or not yet meaningful.
  </Accordion>

  <Accordion title="NIGHT_SUBMITTED — editable modules">
    - Orders: morning save (`canEditMorningEntries` → `NIGHT_SUBMITTED`, `REOPENED`)
    - Collections: morning save (`canEditMorningCollections`)
    - Collections: continued night save (`canEditNightCollections` remains true here)
    - Purchase (`canEditPurchases` → `NIGHT_SUBMITTED`, `REOPENED`)
    - Vehicle Allocation: MORNING session (active execution session for this state)
    - Trays (`canEditTrays` → `NIGHT_SUBMITTED`, `REOPENED`)
    - Dairy Tray Tracking (`canEditDairyTrayTracking` → `NIGHT_SUBMITTED`, `REOPENED`)
    - Cash Settlement: route expenses (`canEditRouteExpenses` → `NIGHT_SUBMITTED`, `REOPENED`), route denominations, direct collections, bank deposits (each → `NIGHT_SUBMITTED` only)

    Night order entry (`canEditNightEntries`) is blocked here.
  </Accordion>

  <Accordion title="MORNING_SUBMITTED — editable modules">
    - Collections: admin save (`canAdminEditCollections` → `MORNING_SUBMITTED`, `REOPENED`) writes `online_collection`, `bank_deposit`, `admin_remarks`.
    - Everything else: read-only. Route denominations, direct collections, and bank deposits are frozen (they only allow edits in `NIGHT_SUBMITTED`).
  </Accordion>

  <Accordion title="FINALIZED — editable modules">
    None. The only allowed write is `reopen`, which requires `ADMIN` and a non-empty reason.
  </Accordion>

  <Accordion title="REOPENED — editable modules">
    Almost every `canEdit…` helper is true in `REOPENED`:

    - Orders: morning save
    - Collections: night, morning, and admin saves
    - Purchase
    - Vehicle Allocation: both NIGHT and MORNING sessions (execution module bypass in `REOPENED`)
    - Trays and Dairy Tray Tracking
    - Cash Settlement: route expenses only. Route denominations, direct collections, and bank deposits are still restricted to `NIGHT_SUBMITTED`, so they cannot be re-entered from `REOPENED`.
    - Distributor Transfer regeneration (`canEditDistributorTransfers` → `REOPENED` only)

    Night order entry (`canEditNightEntries`) is not re-enabled by reopen. Corrections happen through morning/delivered quantities instead.
  </Accordion>
</AccordionGroup>

## Who triggers what

The `@Roles` decorator declares the minimum role required. The `RolesGuard` uses a hierarchy where `ADMIN` (2) satisfies any `EMPLOYEE` (1) requirement, so admins can also call employee-tagged endpoints.

| Endpoint | Minimum role |
| --- | --- |
| `POST /papers` | `EMPLOYEE` |
| `POST /papers/:id/submit-night` | `EMPLOYEE` |
| `POST /papers/:id/submit-morning` | `EMPLOYEE` |
| `POST /papers/:id/finalize` | `ADMIN` |
| `POST /papers/:id/reopen` | `ADMIN` |

The `RolesGuard` enforces the role check at request time; `WorkflowStateService.validateTransition` enforces transition legality.

## Timestamp fields

| Column | Set on | Cleared |
| --- | --- | --- |
| `night_entry_submitted_at` | `submit-night` | Never |
| `morning_entry_submitted_at` | `submit-morning` | Never |
| `finalized_at` | `finalize` (every time, including after re-finalize from REOPENED) | Never |
| `reopened_at` | `reopen` | Never |
| `reopen_reason` | `reopen` | Never |

The timestamps form an audit trail. Once a paper has ever been submitted or finalized, that fact is preserved permanently in these columns.
