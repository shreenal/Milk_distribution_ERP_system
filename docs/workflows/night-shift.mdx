The **night shift** is the first half of a business day in the ERP. It begins in the evening of the calendar day _before_ the sale date and ends when an employee submits the night entry, transitioning the paper from `DRAFT` to `NIGHT_SUBMITTED`. This page walks through the shift as a story, in the order the actions happen.

## Preconditions

Before the night shift begins:

- Master data must be current: active clients, delivery groups, distributors, group supply rules, product links, and client rates that cover the target sale date.
- No paper yet exists for the target sale date. (If one exists, the create endpoint returns the existing paper instead of creating a duplicate.)

## Step 1 — Paper creation

The paper is created via `POST /papers` with a `date` (the sale date). The endpoint is decorated `@Roles('EMPLOYEE')`, so either an `EMPLOYEE` or an `ADMIN` may call it (Admin passes the `EMPLOYEE` role check through the hierarchy in `RolesGuard`). Business practice is that an Admin owns paper creation; the code does not enforce that. The service:

1. Rejects the request if `date` is before today or more than 30 days ahead. "Today" is the current business day in the **Asia/Kolkata (IST)** calendar (`DATE_CONFIG.TIMEZONE`). The requested sale date is compared against the IST business day; dates continue to be stored internally as date-only values normalized to UTC midnight.
2. Confirms at least one active delivery group exists.
3. Inserts one `order_paper` row with `status = DRAFT`, `sale_date = date`, and `order_date = date − 1 day` (derived by `resolvePaperSaleDate`). The `@unique` on `order_date` enforces one paper per sale date.
4. Auto-creates one `order_sheet` per active delivery group, linked to that paper.

The paper is now visible on the operations screen with a status badge of `DRAFT`.

## Step 2 — Employees enter night orders

Employees walk their routes (or take orders by phone) and, for each order sheet, save the client's ordered quantity for each product. The request is `POST /orders/sheet/:sheetId/night-save` with an array of items.

For each item, the service:

- Confirms the paper's status is `DRAFT`. Any other status is rejected.
- Resolves the selling rate via `OrdersRepository.getSellingRate` — client-specific rate first (`master_client_rate_product`), then falls back to the distributor's default rate (`distributor_product_rate`). If neither is active on the sale date, the entire batch is rejected.
- Rejects duplicates within the batch (same `(client, product_link)` twice).
- Confirms the client belongs to the sheet's delivery group.
- Upserts `order_sheet_items` with `ordered_qty`, `night_selling_rate`, and `night_bill_amount = ordered_qty × night_selling_rate`.

At this point the paper is a night plan: for each route and each client, we know what they asked for and at what rate.

## Step 3 — Employees record night collections

While on the route, employees also receive payments. For each order sheet and each supply category the client participates in, the employee saves the amounts collected. Endpoints:

- `POST /collections/sheet/:sheetId/milk/night-save`
- `POST /collections/sheet/:sheetId/non-milk/night-save`

The request contains, per client, `cash_collection`, `cheque_collection`, `online_collection`, `office_amount_given`, `bank_deposit`, and `employee_remarks`. The row keyed by `(order_sheet_id, client_id, category)` is upserted.

## Step 4 — Employees plan the night vehicle allocation

For each vehicle and each distributor whose stock the vehicle will carry that night, the employee records the planned quantity by product. Endpoint:

- `POST /vehicle-allocations/:paperId/vehicle-allocations`

The service creates or updates the `vehicle_allocation_paper` row for `(paper, NIGHT)` and its child `vehicle_allocation` rows keyed by `(vehicle, distributor, category, product)`. It also writes `vehicle_distribution_assignment` rows (`(vehicle, category)` → distributor) so the morning purchase step can find them.

<Note>
  Vehicle allocation is per-session, not per-paper. The morning session gets its own set of allocations later.
</Note>

## Step 5 — Employee submits the night entry

Once night orders, night collections, and the night vehicle allocation are complete, an employee calls `POST /papers/:paperId/submit-night`. The service runs a cross-module **readiness check** through `PaperValidationService` before the transition. It refuses to close the night if any of the following is incomplete:

- Night vehicle allocations missing or vehicle-distribution assignments unset.
- Night order entries missing on any sheet.
- Tray calculations missing on any sheet.
- Night collections missing on any sheet.

Only after readiness passes does the service:

- Validate the transition `DRAFT → NIGHT_SUBMITTED` via `WorkflowStateService.validateTransition()`.
- Update the paper's `status` to `NIGHT_SUBMITTED` and stamp `night_entry_submitted_at`.

## After night submit

- Night order and night collection endpoints are now closed. Any attempt to save them returns a business-rule error.
- Morning entry endpoints (delivered qty, purchase, morning collections, trays, dairy trays, morning vehicle allocation) are now open.
- The night session is effectively frozen and ready for delivery.

## Diagram

```text
Admin → POST /papers                       (creates DRAFT + auto sheets)
Employee → POST /orders/sheet/:id/night-save
Employee → POST /collections/sheet/:id/{milk,non-milk}/night-save
Employee → POST /vehicle-allocations/:paperId/vehicle-allocations (NIGHT session)
Employee → POST /papers/:paperId/submit-night   → status becomes NIGHT_SUBMITTED
```

## Common issues on the night shift

<AccordionGroup>
  <Accordion title="Save is rejected: no active rate">
    Neither an active `master_client_rate_product` for the `(client, product_link)` nor an active `distributor_product_rate` on the `product_link` covers the sale date. Add a client rate, or make sure the distributor's default rate is active, before retrying.
  </Accordion>

  <Accordion title="Save is rejected: client not in delivery group">
    A save attempted to include a client that is not in the sheet's delivery group. Verify the client's `delivery_group_id` and re-open the correct order sheet.
  </Accordion>

  <Accordion title="submit-night rejected">
    Paper status was not `DRAFT`. Check whether the paper has already been submitted, and query `/papers/:paperId` to see the current status.
  </Accordion>
</AccordionGroup>
