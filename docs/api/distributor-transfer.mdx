The Distributor Transfer API surfaces the inter-distributor transfer records generated when a supplier distributor differs from a client's owner distributor. These records are auto-created inside `PaperService.submitMorningEntryService` (which calls `DistributorTransferService.generateTransfer`). The API also exposes a manual `generate` endpoint used after `REOPENED` edits.

The controller is mounted at `@Controller('distributor-transfer')` with `:paperId` as the leading path segment.

---

## GET /distributor-transfer/:paperId

### Purpose

Returns the transfer summary and grid for the paper: the `order_paper` header, and the per-`(supplier_distributor, owner_distributor)` grid built from source `order_sheet_items`.

### Access control

`EMPLOYEE` (and above).

### Response

Returns HTTP **200** with `{ paper, ...transferGrids }` where each grid entry represents a `(supplier_distributor, owner_distributor)` pair and its rows keyed by `billingGroup` with product-quantity columns.

---

## POST /distributor-transfer/:paperId/generate

### Purpose

Rebuilds `distributor_transfer` rows for the paper. The service reads source items, computes per-`(supplier, owner, billing_group, product)` totals, validates that each `(supplier, owner)` pair is whitelisted in `distributor_transfer_rule`, then replaces the paper's transfers in a single transaction.

Row shape written: `{ order_paper_id, supplier_distributor_id, owner_distributor_id, billing_group_id, product_id, transfer_qty }`. Uniqueness on `(order_paper_id, supplier_distributor_id, owner_distributor_id, billing_group_id, product_id)`.

### Access control

`EMPLOYEE` (and above). This endpoint is intended for use after a paper is reopened and morning data has been edited; the initial generation happens automatically inside `submit-morning`.

`WorkflowStateService.canEditDistributorTransfers(status)` allows edits only in `REOPENED`; the endpoint itself accepts calls regardless of state, but a corresponding paper transition (submit-morning) is the normal path in `NIGHT_SUBMITTED` → `MORNING_SUBMITTED`.

### Validation and errors

| Scenario | HTTP status | Detail |
| --- | --- | --- |
| Paper not found | `404 Not Found` | `DistributorTransferService` uses `NotFoundException('Order paper not found')` for missing papers. This module is the exception to the module-wide "everything is `BadRequestException`" convention noted in [Error Handling](/architecture/error-handling). |
| A required `(supplier, owner)` pair has no active `distributor_transfer_rule` | `400 Bad Request` | Validation service rejects |
