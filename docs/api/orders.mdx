sidebarTitle: "Orders"

The Orders API is how the client app reads and writes the per-client line items on each order sheet. Every paper has one `order_sheet` per active delivery group; each sheet holds one `order_sheet_items` row per (client, product\_link) combination. Night-shift operators enter `orderedQty` at the start of the cycle; morning-shift operators enter `deliveredQty` after the route completes. All billing amounts (GST inclusive/exclusive, final bill) are recomputed server-side on every save.

All endpoints require a bearer token. `EMPLOYEE` role is enforced by the controller; `ADMIN` inherits `EMPLOYEE` access via the role hierarchy.

---

## GET /orders/sheet/:sheetId

### Purpose

Returns the full sheet payload used by the Orders Page: the sheet record, workflow flags for the current paper state, and the two billing grids (`milkGrid` and `nonMilkGrid`) built from active clients, active products, and the current `order_sheet_items` rows.

### Path parameters

<ParamField path="sheetId" type="number" required>
  Numeric primary key of the `order_sheet`.
</ParamField>

### Response

Returns HTTP **200** with:

<ResponseField name="sheet" type="object">
  The `order_sheet` row plus its `order_paper` relation (id, status, `order_date`, `sale_date`, submission timestamps).
</ResponseField>

<ResponseField name="workflow" type="object">
  Feature flags derived from `WorkflowStateService`, used by the client to enable or disable actions on the current paper state.
</ResponseField>

<ResponseField name="milkGrid" type="object">
  Product columns, one row per active MILK client on the sheet's delivery group, and totals. The quantity cells reflect `ordered_qty` when the paper is in `DRAFT` or `REOPENED`, and `delivered_qty` otherwise. `billAmount` mirrors `night_bill_amount` in the ordered case and `final_bill_amount` in the delivered case.
</ResponseField>

<ResponseField name="nonMilkGrid" type="object">
  Same shape as `milkGrid`, for NON\_MILK products.
</ResponseField>

### Validation and errors

| Scenario | HTTP status | Detail |
| --- | --- | --- |
| `sheetId` not a positive integer | `400 Bad Request` | ParseIntPipe rejection |
| Sheet does not exist | `400 Bad Request` | Sheet not found |

## GET /orders/sheet/:sheetId/items

### Purpose

Returns the raw `order_sheet_items` array for a sheet, without grid construction. Used by clients that need the underlying rows (rates, GST fields, both night and final amounts) rather than the presentation grids.

### Response

Returns HTTP **200** with an array of `order_sheet_items` rows including `product_id`, `product_link_id`, `ordered_qty`, `delivered_qty`, `night_selling_rate`, `night_bill_amount`, `final_selling_rate`, `final_taxable_amount`, `final_gst_percentage`, `final_gst_amount`, and `final_bill_amount`.

## POST /orders/sheet/:sheetId/night-save

### Purpose

Saves the ordered quantities entered during the night shift. The request body is an array of `SaveNightEntriesDto` items — no wrapping object.

### Behavior

- Editable only when the parent paper's status passes `WorkflowStateService.canEditNightEntries`, which is `DRAFT` only.
- The service validates each client (exists and active), validates each client belongs to the sheet's delivery group, resolves the `product_link_id` from the group's supply rules, and looks up the selling rate from `master_client_rate_product` (fallback: `distributor_product_rate`).
- On save, `ordered_qty`, `night_selling_rate`, and `night_bill_amount = ordered_qty × night_selling_rate` are upserted.
- GST fields remain null until morning save.

### Access control

`EMPLOYEE` (and above, via hierarchy).

### Request body

Direct array of items — the endpoint expects `SaveNightEntriesDto[]` in the body root, not an `items` wrapper.

<ParamField body="clientId" type="number" required>
  Client on the sheet.
</ParamField>

<ParamField body="productId" type="number" required>
  Product being ordered.
</ParamField>

<ParamField body="orderedQty" type="number" required>
  Non-negative decimal quantity, maximum `10000`.
</ParamField>

#### Example request

```json
POST /orders/sheet/42/night-save
Authorization: Bearer <token>
Content-Type: application/json

[
  { "clientId": 101, "productId": 7,  "orderedQty": 20 },
  { "clientId": 101, "productId": 12, "orderedQty": 5 },
  { "clientId": 102, "productId": 7,  "orderedQty": 15 }
]
```

### Response

Returns HTTP **201** with `{ success: true, message: "Night entries saved successfully", ... }`.

### Validation and errors

| Scenario | HTTP status | Detail |
| --- | --- | --- |
| Paper status not editable for night entry | `400 Bad Request` | `Cannot edit night entries when paper is <status>. Allowed statuses: DRAFT, REOPENED` |
| Duplicate `(clientId, productId)` in payload | `400 Bad Request` | `Duplicate entries found: ...` (validated by `OrdersValidationService.validateNoDuplicates`) |
| Client inactive or unknown | `400 Bad Request` | `Client with ID <id> not found` / `Client "<name>" is inactive and cannot be ordered` |
| Client not in delivery group | `400 Bad Request` | `Client <id> does not belong to group <groupId>` |
| Rate not configured for the resolved `product_link` | `400 Bad Request` | `No active rate found for product <id> on date <date>` |
| `orderedQty` negative | `400 Bad Request` | DTO `@Min(0)` rule |
| `orderedQty` greater than `10000` | `400 Bad Request` | DTO `@Max(10000)` rule |

## POST /orders/sheet/:sheetId/morning-save

### Purpose

Saves the delivered quantities recorded during the morning shift. Writes `delivered_qty`, `final_selling_rate`, `final_taxable_amount`, `final_gst_percentage`, `final_gst_amount`, and `final_bill_amount` on each `order_sheet_items` row.

### Behavior

- Editable when `WorkflowStateService.canEditMorningEntries(status)` returns true — that is, when the paper is in `NIGHT_SUBMITTED` or `REOPENED`.
- Rate resolution runs again at morning save so any rate change between night and morning is captured on the final fields.
- Final GST calculation follows the product's `is_gst_inclusive`/`gst_percentage` at morning save time (see [Order Sheet](/data-model/order-sheet)).

### Access control

`EMPLOYEE` (and above).

### Request body

Direct array of `SaveMorningEntriesDto`:

<ParamField body="deliveredQty" type="number" required>
  Non-negative decimal, maximum `10000`.
</ParamField>

### Validation and errors

| Scenario | HTTP status | Detail |
| --- | --- | --- |
| Paper not in `NIGHT_SUBMITTED` or `REOPENED` | `400 Bad Request` | `Cannot edit morning entries when paper is <status>. Allowed statuses: NIGHT_SUBMITTED, REOPENED` |
| Duplicate `(clientId, productId)` in payload | `400 Bad Request` | `Duplicate entries found: ...` |
| Morning entry references a client/product with no prior night entry | `400 Bad Request` | `No ordered quantity found for Client <id>, Product <id>` |
| `deliveredQty` negative | `400 Bad Request` | DTO `@Min(0)` rule |
| `deliveredQty` greater than `10000` | `400 Bad Request` | DTO `@Max(10000)` rule |
| Rate not configured | `400 Bad Request` | `No active rate found for product <id> on date <date>` |
