The Vehicle Allocations API plans the daily loading schedule for one delivery session. The service reads the active execution session from the paper's status: `DRAFT` → `NIGHT`, `NIGHT_SUBMITTED` → `MORNING`. In `REOPENED`, either session may be re-saved.

The controller is mounted at `@Controller('vehicle-allocations')` with the compound path `:paperId/vehicle-allocations` for both GET and POST.

---

## GET /vehicle-allocations/:paperId/vehicle-allocations

### Purpose

Returns the allocation grid for the active delivery session of the given paper: the `vehicle_allocation_paper`, its `vehicle_allocation` rows (per `(vehicle, distributor, category, product)`), and its `vehicle_distribution_assignment` rows (per `(vehicle, category)`), plus any metadata needed by the client.

### Access control

`EMPLOYEE` (and above).

### Response

Returns HTTP **200** with the grid built by `VehicleAllocationService.getVehicleAllocations`.

---

## POST /vehicle-allocations/:paperId/vehicle-allocations

### Purpose

Upserts the vehicle allocation for the active delivery session. Writes two related tables in a single transaction:

- `vehicle_allocation` — per `(vehicle_allocation_paper_id, vehicle, distributor, category, product)` with `allocated_qty`.
- `vehicle_distribution_assignment` — per `(vehicle_allocation_paper_id, vehicle, category)` recording which distributor's stock the vehicle is carrying for that category.

### Access control

`EMPLOYEE`. Editable when `WorkflowStateService.canEditVehicleAllocations(status, session)` returns true — that is, when `(status, session)` matches the active execution session, or when the paper is `REOPENED`.

### Request body

`SaveVehicleAllocationDto`:

<ParamField body="allocations" type="array" required>
  Array of `{ vehicleId, distributorId, category (MILK | NON_MILK), productId, allocatedQty }`.
</ParamField>

<ParamField body="assignments" type="array" required>
  Array of `{ vehicleId, milkDistributorId?, nonMilkDistributorId? }`. Each vehicle appears once; unset fields keep the vehicle unassigned for that category.
</ParamField>

#### Example request

```json
POST /vehicle-allocations/128/vehicle-allocations
Authorization: Bearer <token>
Content-Type: application/json

{
  "allocations": [
    { "vehicleId": 3, "distributorId": 5, "category": "MILK",     "productId": 7,  "allocatedQty": 40 },
    { "vehicleId": 3, "distributorId": 5, "category": "MILK",     "productId": 12, "allocatedQty": 15 },
    { "vehicleId": 3, "distributorId": 6, "category": "NON_MILK", "productId": 21, "allocatedQty": 10 }
  ],
  "assignments": [
    { "vehicleId": 3, "milkDistributorId": 5, "nonMilkDistributorId": 6 }
  ]
}
```

### Validation and errors

| Scenario | HTTP status | Detail |
| --- | --- | --- |
| Paper status/session combination not editable | `400 Bad Request` | Wrong session for the paper's current state and not `REOPENED` |
| Distributor cannot supply the product's `(brand, product_group, category)` | `400 Bad Request` | No active `distributor_procurement_rule` |
| Product's category does not match entry `category` | `400 Bad Request` | Validation service rejects |
