Each backend module owns one slice of the domain. Boundaries are defined by which entity the module writes to; multi-entity workflows compose these modules through the shared `WorkflowStateService` rather than crossing directly into another module's tables.

## Module table

| Module | Owns writes to | Key service methods | Depends on |
| --- | --- | --- | --- |
| `auth` | `user` | `login`, `validateUser`, `verifyToken` | (no domain dependencies) |
| `paper` | `order_paper`, `order_sheet` | `generatePaper`, `submitNight`, `submitMorning`, `finalize`, `reopen` | `workflow`, `orders`, `distributor-transfer` |
| `orders` | `order_sheet_items` | `getSheet`, `saveNightItems`, `saveMorningItems` | `workflow`, `products`, `clients` |
| `collections` | `client_collection` | `getSheetCollections`, `saveEmployeeEntry`, `saveAdminEntry` | `workflow` |
| `purchase` | `purchase_paper`, `purchase_entry` | `getPurchasePaper`, `savePurchaseEntries` | `workflow`, `products`, `vehicle-allocation` |
| `vehicle-allocation` | `vehicle_allocation_paper`, `vehicle_allocation_entry` | `getAllocation`, `saveAllocation` | `workflow` |
| `trays` | `client_tray_transaction` | `getSheetTrays`, `saveTrays` | `workflow`, `products` (rule matching) |
| `dairy-tray-tracking` | `dairy_tray_paper` | `getDairyTrays`, `saveDairyTrays` | `workflow`, `trays` |

## Shared cross-cutting services

Two services are injected across almost every module:

- **`WorkflowStateService`** — pure boolean methods keyed on `PaperStatus`. Every write-side service calls it before mutating; no module implements state gating on its own.
- **`PrismaService`** — the singleton Prisma client, used by services (via `$transaction`) and repositories (via query builders).

Two shared repositories live under `common/repositories`:

- **`OrderItemsRepository`** — reused by `orders`, `delivery-summary`, and `distributor-transfer`.

## Why the split matters

- **Feature isolation:** a bug in `cash-settlement` never touches order data.
- **Testability:** each module can be tested against a small set of collaborators.
- **Auditability:** each mutating action lives in exactly one service, so tracing "who wrote this field" is a single search.
