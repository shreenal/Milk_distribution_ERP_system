Clients are the end customers. Each client belongs to two groups — a **billing group** (how invoices are aggregated) and a **delivery group** (which route serves them). The two are separate because a client can be billed centrally while receiving deliveries on a specific route.

## master\_client

| Column | Notes |
| --- | --- |
| `id` | PK |
| `code` | Unique short code used in printed papers |
| `name` | Full client name |
| `shop_name` | Optional trading name |
| `contact` | Phone number |
| `billing_group_id` | FK → `master_group` (relation `BillingGroup`) |
| `delivery_group_id` | FK → `master_group` (relation `DeliveryGroup`) |
| `owner_distributor_id` | The distributor that "owns" this client for accounting |
| `is_active` | Soft delete |
| `created_at`, `updated_at` |  |

Uniqueness: `code` is unique across all clients.

## master\_group

Groups serve dual purposes distinguished only by which foreign key points to them:

- When referenced as `billing_group_id` — an invoicing bucket. The delivery summary rolls up by billing group.
- When referenced as `delivery_group_id` — a route. The `order_sheet` for a paper is created per delivery group.

| Column | Notes |
| --- | --- |
| `id` | PK |
| `name` | Group name |
| `vehicle_id` | FK → `master_vehicle`, nullable — default vehicle for the group |
| `delivery_session` | `DeliverySession` enum, default `NIGHT` — which shift serves this delivery group |
| `is_active` | Soft delete |

## master\_client\_category

Many-to-many join between `master_client` and the `SupplyCategory` enum (`MILK`, `NON_MILK`). One row per `(client_id, category)`; the composite PK is `(client_id, category)`. A client may be enrolled in one or both categories, which controls whether they appear in the MILK grid, the NON\_MILK grid, or both on each order sheet.

## client\_collection

Payment records, one row per (order sheet, client, category).

| Column | Notes |
| --- | --- |
| `id` | PK |
| `order_sheet_id` | FK; cascade delete |
| `client_id` | FK → `master_client` |
| `category` | `MILK` or `NON_MILK` — separate rows per category per client |
| `cash_collection` | Cash received on route |
| `cheque_collection` | Cheque received on route |
| `online_collection` | Online transfer received on route |
| `office_amount_given` | Cash paid at office |
| `bank_deposit` | Deposited on client's behalf |
| `employee_remarks` | Free text captured by driver |
| `admin_remarks` | Free text captured by admin |
| `created_at`, `updated_at` |  |

Uniqueness: `@@unique([order_sheet_id, client_id, category])`.

## Why billing group and delivery group are separate

A common configuration: one large client (a hotel chain) is billed as a single account (one `billing_group`) but has ten physical outlets each on a different route (ten `delivery_group_id`s across ten `master_client` rows). Billing group totals aggregate all outlets while each outlet keeps its own delivery paper.
