The Milk Distribution ERP database is built around a single central document — the **Order Paper** — with every operational entity linked back to it either directly or through an order sheet. This overview groups the entities by functional area and links to the detailed model pages.

## Entity map (top-down)

```text
order_paper (1 per day)
├── order_sheet (1 per delivery group)
│   ├── order_sheet_items (1 per client × product)
│   │   ├── client_collection (payment channels)
│   │   └── client_tray_transaction (crate accounting)
│   └── (linked to master_group → master_client)
├── purchase_paper (1 per vehicle × session)
│   └── purchase_entry (1 per product loaded)
├── vehicle_allocation_paper
│   └── vehicle_allocation_entry
├── dairy_tray_paper (depot-level trays)
├── distributor_transfer (auto-generated, audit trail)
├── cash_route_settlement (per vehicle, per session)
├── cash_route_expense
├── cash_direct_collection
└── cash_bank_deposit
```

## Master data (independent of paper)

- `master_dairy`, `master_brand`, `master_product_type`, `master_product`, `master_product_variant`
- `master_distributor`, `distributor_procurement_rule`, `distributor_product_rate`, `distributor_transfer_rule`
- `master_client`, `master_group`, `master_client_category`
- `master_vehicle`, `master_driver`
- `master_tray_type`, `product_tray_rule`
- `master_bank`
- `user` (auth)
