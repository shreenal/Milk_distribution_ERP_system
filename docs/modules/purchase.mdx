## Purpose

The Purchase module records what each vehicle actually picked up from the dairy for each product link, for each delivery session. It is the counterpart to Vehicle Allocation (the plan) — Purchase records the reality.

## Responsibilities

- Create the `purchase_paper` on first save for a given paper.
- Upsert `purchase_entry` rows keyed by `(purchase_paper, delivery_session, vehicle, product_link)`.
- Apply the brand's `gatepass_date_policy` to default `gatepass_date` when not provided.
- Upsert `purchase_variance_acknowledgement` rows submitted alongside purchase entries when the allocated vs purchased quantity variance requires operator sign-off.

## Business rules

- Writes require `NIGHT_SUBMITTED` or `REOPENED`.
- `gatepass_date_policy` = `SAME_DAY` sets default gatepass to sale date; `PREVIOUS_DAY` sets it to sale date minus one.
- The distributor on a purchase entry must match the distributor on the product link.
- A variance acknowledgement is stored per `purchase_entry` and records the reason, optional remarks, and the acknowledging user. Acknowledgements are preserved across REOPENED; the variance itself is always recomputed from the current allocations and purchases and must be re-reviewed if it has changed.

## Dependencies

- `PrismaService` — reads and writes `purchase_paper`, `purchase_entry`.
- `WorkflowStateService` — status-gated writes.
- Master data — reads `master_product_link` and `master_brand` (for the gatepass policy).

## Endpoints

| Method | Path | Role | Purpose |
| --- | --- | --- | --- |
| `GET` | `/purchases/:paperId` | EMPLOYEE | Return purchases for a paper |
| `POST` | `/purchases/:paperId` | EMPLOYEE | Save (upsert) purchase entries |

## Request flow

```text
POST /purchases/:paperId
  → PurchaseController
  → PurchaseService.savePurchases(paperId, dto)
       ensure purchase_paper exists (create if missing)
       for each entry:
         default gatepass_date from brand policy if omitted
         upsert purchase_entry (purchased_qty, purchase_rate, purchase_amount)
       for each acknowledgement in dto.acknowledgements:
         upsert purchase_variance_acknowledgement (reason, remarks, acknowledged_by)
```

## Database tables

- `purchase_paper`, `purchase_entry`, `purchase_variance_acknowledgement` — see [Vehicles](/data-model/vehicles).

## Lifecycle

```text
NIGHT_SUBMITTED / REOPENED   → POST /purchases/:paperId (upsert)
FINALIZED                    → read-only via GET /purchases/:paperId
```
