## Purpose

The Workflow module owns the paper state machine and every `canEdit*` decision that other transaction modules consult before writing. It has no controller and no repository — it is a pure services \+ types package that `WorkflowModule` exports for injection.

## Files

```text
src/modules/transactions/workflow/
├── workflow-state.service.ts      # WorkflowStateService (validateTransition, canEdit*, shouldValidate*)
├── workflow.builder.ts            # WorkflowBuilder — per-module response envelopes
├── workflow.module.ts             # Exports both services
├── constants/
│   └── workflow-status.constants.ts
├── guards/
│   └── workflow-status.guard.ts    # Reserved; currently not registered on any route
└── types/
    └── workflow.types.ts
```

## State machine (`OrderPaperStatus`)

```text
DRAFT → NIGHT_SUBMITTED → MORNING_SUBMITTED → FINALIZED
                                                    ↓
                                                REOPENED → FINALIZED
```

`WorkflowStateService.validateTransition(currentStatus, target)` is the single guard for state changes. It rejects any other pairing with `BadRequestException`.

## `canEdit*` methods

| Method | Editable when status is |
| --- | --- |
| `canEditNightEntries(status)` | `DRAFT` |
| `canEditMorningEntries(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditNightCollections(status)` | `DRAFT`, `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditMorningCollections(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canAdminEditCollections(status)` | `MORNING_SUBMITTED`, `REOPENED` |
| `canEditTrays(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditPurchases(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditDairyTrayTracking(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditEmployeeCollections(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditVehicleAllocations(status, session)` | `DRAFT` \+ `NIGHT`, `NIGHT_SUBMITTED` \+ `MORNING`, or `REOPENED` (either session) |
| `canEditRouteExpenses(status)` | `NIGHT_SUBMITTED`, `REOPENED` |
| `canEditRouteDenominations(status)` | `NIGHT_SUBMITTED` |
| `canEditDirectCollections(status)` | `NIGHT_SUBMITTED` |
| `canEditBankDeposits(status)` | `NIGHT_SUBMITTED` |
| `canEditDistributorTransfers(status)` | `REOPENED` |
| `canFinalize(status)` | `MORNING_SUBMITTED`, `REOPENED` |

The service also exposes:

- `getActiveExecutionSession(status)` — returns `NIGHT` for `DRAFT`, `MORNING` for `NIGHT_SUBMITTED`; throws `BadRequestException` for any other status.
- `shouldValidateVehicleAllocations(status, session)`, `shouldValidatePurchases(status)`, `shouldValidateDeliveredQuantity(status)`, `shouldValidateTrays(status)`, `shouldValidateEmployeeCollections(status)`, `shouldValidateDairyTrayTracking(status)` — used by services that need to know whether to run validation but not necessarily block writes.

Internally, two `private` helpers back most of the public `canEdit*` methods:

- `canEditCompletionModule(status)` returns `true` for `NIGHT_SUBMITTED` and `REOPENED`. Used by morning entries, trays, purchases, dairy-tray-tracking, employee collections, and route expenses.
- `canEditExecutionModule(status, session)` returns `true` in `REOPENED` for either session, `NIGHT` in `DRAFT`, and `MORNING` in `NIGHT_SUBMITTED`. Used by vehicle allocations.

## `WorkflowBuilder`

Builds the workflow envelope returned to the frontend from each read endpoint. All methods take an `OrderPaperStatus` (`buildVehicleAllocationWorkflow` also takes a `DeliverySession`) and return a small object shaped per module:

| Method | Return shape |
| --- | --- |
| `buildOrdersWorkflow(status)` | `{ status, editable }` — `editable = canEditNightEntries \|\| canEditMorningEntries` |
| `buildTraysWorkflow(status)` | `{ status, editable }` — `editable = canEditTrays` |
| `buildPurchasesWorkflow(status)` | `{ status, editable }` — `editable = canEditPurchases` |
| `buildDairyTrayTrackingWorkflow(status)` | `{ status, editable }` — `editable = canEditDairyTrayTracking` |
| `buildVehicleAllocationWorkflow(status, session)` | `{ status, editable }` — `editable = canEditVehicleAllocations(status, session)` |
| `buildCollectionsWorkflow(status)` | `{ status, permissions: { canEditNightCollections, canEditMorningCollections, canEditAdminCollections, canFinalize } }` |
| `buildCashSettlementWorkflow(status)` | `{ status, permissions: { canEditRouteExpenses, canEditRouteDenominations, canEditDirectCollections, canEditBankDeposits } }` |
| `buildDistributorTransferWorkflow(status)` | `{ status }` — no boolean fields; the frontend consults `canEditDistributorTransfers` directly for the `REOPENED`-only regenerate action |

## Dependencies

None. `WorkflowStateService` is pure; it takes a status (and optionally a session) and returns a boolean.

## Consumers

Every mutating transaction service imports `WorkflowStateService`:

- `PaperService` — `validateTransition` for status changes.
- `OrdersService`, `CollectionsService`, `TraysService`, `PurchaseService`, `VehicleAllocationService`, `DairyTrayTrackingService`, `DistributorTransferService`, `CashSettlementService` — all check the relevant `canEdit*` before upserting.
