## Purpose

The Paper module owns the daily `order_paper` record — the single container everything else in the system belongs to. It is the only module that can transition paper status, and every other module reads the paper's status before allowing writes.

## Responsibilities

- Create the day's paper for a given `sale_date`, and auto-generate one `order_sheet` per active delivery group.
- Read the paper by ID, by date, or "today's" paper.
- Transition status: submit-night, submit-morning, finalize, reopen.
- Enforce the state machine via `WorkflowStateService.validateTransition()`.
- Run cross-module **readiness validation** before every business transition. `PaperValidationService` composes the per-module validation services (Orders, Vehicle Allocation, Client Trays, Collections, Purchase, Cash Settlement, Distributor Transfer, Dairy Trays) so that submit-night, submit-morning, and finalize each fail fast if any upstream module is incomplete or inconsistent.

## Business rules

- Exactly one paper per calendar sale date. The DB-level uniqueness is on `order_paper.order_date` (`@unique @db.Date`), which the repository derives as `sale_date − 1 day` via `resolvePaperSaleDate`. `sale_date` itself is not `@unique`.
- Sale date cannot be in the past or more than 30 days ahead.
- Requires at least one active delivery group to create sheets.
- Only Admins can finalize or reopen; the reopen reason is mandatory.
- Reopen preserves earlier timestamps; only `finalized_at`, `reopened_at`, `reopen_reason` are affected by the correction loop.
- `submit-night` requires: night vehicle allocations and assignments configured; and, for every sheet, night orders complete, tray calculations exist, and night collections are recorded.
- `submit-morning` requires: for every sheet, morning entries complete with sane quantities, tray movements complete, and morning collections recorded; and, for the paper as a whole, purchases complete, dairy trays complete, distributor-transfer rules exist for every required supplier→owner pair, and cash-settlement route denominations plus bank-deposit reconciliation succeed (skipped in `REOPENED` because cash settlement is treated as historical).
- `finalize` requires admin-only collection fields to be recorded on every sheet.

See [Business Rules — Paper Creation and Lifecycle](/domain/business-rules) for the full list.

## Dependencies

- `PrismaService` — writes and reads `order_paper` and `order_sheet`.
- `WorkflowStateService` — the shared state-machine validator.
- `PaperValidationService` — composes readiness checks across every downstream module before a status transition proceeds.
- Master data — reads `master_group` to auto-create sheets.
- Distributor Transfer service — invoked at `submit-morning` to auto-generate transfers.

## Endpoints

| Method | Path | Role | Purpose |
| --- | --- | --- | --- |
| `POST` | `/papers` | EMPLOYEE | Create paper for the given `date`; auto-creates sheets |
| `GET` | `/papers/today` | EMPLOYEE | Return `{type: "TODAY", paper}` if today's paper exists, otherwise `{type: "LATEST", paper}` for the most recent paper. Throws `400 Bad Request` (`NO_PAPERS_FOUND`) only when the database has no papers at all. |
| `GET` | `/papers` | EMPLOYEE | List papers, optionally filtered by `date` |
| `GET` | `/papers/:paperId` | EMPLOYEE | Read one paper with sheets |
| `POST` | `/papers/:paperId/submit-night` | EMPLOYEE | Transition `DRAFT → NIGHT_SUBMITTED` |
| `POST` | `/papers/:paperId/submit-morning` | EMPLOYEE | Transition `NIGHT_SUBMITTED → MORNING_SUBMITTED`; auto-generate transfers |
| `POST` | `/papers/:paperId/finalize` | ADMIN | Transition `MORNING_SUBMITTED` or `REOPENED` → `FINALIZED` |
| `POST` | `/papers/:paperId/reopen` | ADMIN | Transition `FINALIZED → REOPENED` (requires `reason`) |

## Request flow

```text
HTTP request → PaperController
             → JwtAuthGuard (auth) → RolesGuard (role)
             → PaperService.<action>
             → PaperValidationService.validate<Action>Readiness() (for submit-night, submit-morning, finalize)
             → WorkflowStateService.validateTransition() (for status changes)
             → PrismaService (order_paper[, order_sheet[]])
             → (submit-morning only) DistributorTransferService.generateTransfer()
             ← response
```

## Database tables

- `order_paper` — see [Order Paper data model](/data-model/order-paper).
- `order_sheet` — one per active delivery group per paper. See [Order Sheet](/data-model/order-sheet).

## Lifecycle

Every paper lives through the sequence:

```text
POST /papers                → DRAFT
POST /papers/:id/submit-night   → NIGHT_SUBMITTED
POST /papers/:id/submit-morning → MORNING_SUBMITTED     (side effect: distributor_transfer[])
POST /papers/:id/finalize       → FINALIZED
(optional) POST /papers/:id/reopen  → REOPENED → finalize → FINALIZED
```

See [Paper States](/workflows/paper-states) for the full state machine and [Reopen Workflow](/workflows/reopen-workflow) for the correction loop.
